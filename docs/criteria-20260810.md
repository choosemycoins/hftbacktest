- Связано: [`proposal-20260810.md`](proposal-20260810.md),

- Метод: критерии сформулированы по измеренному live fill-quality, offline signal study, shadow-артефактам и operational constraints; часть численных margins требует явного выбора владельца эксперимента до расчёта power

## 1. Зачем нужен отдельный документ

У `#20` уже есть сильный offline proxy-result, но ещё нет binding accept на наших реальных fill'ах.
Опасность следующего шага — смешать четыре разных утверждения:

1. сигнал статистически связан с будущим движением;
2. сигнал выделяет токсичные **наши** fill'ы;
3. бот успевает отменить опасную заявку;
4. после всех costs и потерянных opportunities стратегия имеет положительную абсолютную экономику.

Arm требует одновременного подтверждения всех четырёх утверждений. Хорошая классификация сама по себе
не является торговым edge.

Этот документ отделяет:

- **hard criteria**, следующие из измерений или protocol/safety invariant;
- **computed criteria**, которые должны получиться из power/economics расчёта;
- **policy choices**, зависящие от допустимого риска и минимально полезного дохода;
- **illustrative defaults**, которые нельзя выдавать за эмпирически доказанные константы.

## 3. Основной экономический принцип

### 3.1 Cohort separation недостаточно

Пусть:

- `p` — доля blocked fill notional;
- `mu_r` — realized edge retained cohort;
- `mu_b` — realized edge blocked cohort;
- `d = mu_r - mu_b` — separation;
- `mu_all,W` — unconditional edge на том же eligible окне `W`, из которого получены cohorts.

Тогда:

```text
mu_all,W = (1 - p) * mu_r + p * mu_b
mu_r     = mu_all,W + p * d
```

Identity применима только при одинаковых окне, eligibility rules и notional weights. В Stage A
нельзя объединять `p`/`d` из 36-fill overlap с `mu_all = -3.154 bp` из полной 140-fill session;
нужно посчитать `mu_all,overlap`, а full-session control использовать как representativeness check.

Для интуиции, оставаясь внутри одного proxy population и предполагая равные observation weights:
unconditional около -0.7 bp, blocked adverse decile около -4.5 bp и `p = 0.10` дают:

```text
mu_r,proxy = (-0.7 - 0.10 * -4.5) / 0.90 = -0.278 bp
uplift      = -0.278 - -0.7 = 0.422 bp
```

Extreme-low-vs-high gap 5.5 bp не равен retained-vs-blocked gap при конкретном threshold. Даже
same-proxy иллюстрация не является оценкой actual-fill policy; она показывает только, почему сильная
разница extreme cohorts может давать небольшой средний uplift. Binding расчёт всегда выполняется на
одной frozen policy и одном eligible actual-fill окне. Подробный scale check — в
[`alpha-structural-edge-20260810.md` §3.2](alpha-structural-edge-20260810.md#32-почему-55-bp-separation-ещё-не-означает-прибыль).

### 3.2 Binding primary metric

Для shadow counterfactual:

```text
retained_edge_5s_bps =
    spread_captured_bps
  - maker_fee_bps
  - adverse_5s_bps
  - conservative_funding_and_inventory_bound_bps
  - purchased_weight_cost_bps
```

Все компоненты считаются notional-weighted. Late-cancel candidates, которые консервативная latency
модель считает неуспешно отменёнными, остаются в retained set как losses, а не исчезают из него.

Для requests ведётся точный action ledger. Earned address allowance и отдельный cancel allowance
проверяются feasibility gate'ом; фактически необходимые reserved request weights оцениваются по
текущей цене Hyperliquid `0.0005 USDC/weight` и включаются в edge. При USDC≈USD один купленный weight
на каждый доллар retained filled notional стоит около 5 bp. Точный funding counterfactual в shadow
path-dependent, поэтому
используется консервативная bound/sensitivity; точное funding/inventory accounting является
обязательным уже в armed canary.

### 3.3 Minimum economically useful edge

Владелец эксперимента обязан до power analysis выбрать:

```text
delta_econ_bps =
    required_daily_profit_usd
    / expected_daily_retained_notional_usd
    * 10_000
```

`expected_daily_retained_notional_usd` не подбирается по итоговому run: метод его прогноза и входной
pilot/control window фиксируются вместе с остальной preregistration.

Если отдельная capacity target ещё не определена, предлагаемый временный default для текущей
кампании — `delta_econ = 1.0 bp`. Это **policy choice**, а не оценка из данных. Его мотивация — не
разрешать arm на экономически бессмысленном `epsilon > 0` и оставить запас против shadow path bias.

После просмотра outcomes `delta_econ` менять запрещено.

## 4. Статистическое обоснование

### 4.1 Unit of observation

Fill'ы одного рыночного движения зависимы. Primary inference строится по **hour clusters**, как в live
fill-quality report. Per-fill bootstrap запрещён: он искусственно увеличивает effective sample.

Если диагностика hold/fill dependence покажет, что hour недостаточен, block length увеличивается до
начала outcome analysis и затем фиксируется.

### 4.2 Primary horizon

Primary horizon — **5 s**:

- для него 140/140 coverage в passive control;
- отрицательный edge и decomposition измерены с CI;
- он входит в preregistered signal study;
- 1 s может быть слишком близок к execution transient, 30 s сильнее смешивает последующий regime move.

1 s и 30 s остаются sensitivity checks. Они не образуют три независимых optimisation target и не
дают выбрать «красивый» horizon post hoc.

### 4.3 Confidence rule

Для совместимости с existing report предлагается:

- hour-cluster bootstrap;
- не менее 20,000 resamples;
- two-sided 95% CI;
- заранее фиксированный seed;
- PASS по нижней границе, а не по point estimate.

Binding economic PASS:

```text
LCB95(retained_edge_5s_bps) > delta_econ_bps
```

Выбор 95% — conventional risk choice, а не физическая константа. Его можно заменить только до чтения
outcomes, одновременно зафиксировав стоимость false arm и false reject.

### 4.4 Почему нельзя просто назначить число fill'ов

Для иллюстрации, если временно игнорировать dependence и взять наблюдаемое
`sigma = 7.21 bp`, approximate one-sample size при `alpha = 5%`, power 80%:

```text
n ~= ((z_0.975 + z_0.80) * sigma / effect)^2
  ~= ((1.96 + 0.84) * 7.21 / effect)^2
```

Для `effect = 1 bp` получается около **408 independent observations**.

Для balanced comparison двух cohorts:

```text
n_per_group ~= 2 * ((1.96 + 0.84) * sigma / difference)^2
```

Иллюстративно:

| Minimum detectable difference | iid `n` на cohort |
|---:|---:|
| 5.5 bp | ~27 |
| 3.0 bp | ~91 |

Следствия:

- прежний ориентир «50 blocked fills» разумен только при эффекте, близком к proxy 5.5 bp;
- для 3 bp он недостаточен ещё до поправки на clustering;
- «400 retained fills» — rough iid lower bound для edge около 1 bp, а не готовая preregistration;
- число «60 hour clusters» — conservative floor, но не результат formal power calculation.

### 4.5 Binding sample plan

До clean shadow запускается block-bootstrap power simulation на существующих hourly clusters. В
immutable `sample_plan` фиксируются:

- `delta_econ_bps`;
- `alpha`;
- target power (предлагаемый default: 80%; 90% — более консервативный выбор);
- required eligible hour clusters;
- required retained/blocked notional и fill counts;
- maximum calendar duration;
- treatment of missing/outage clusters;
- exact stop rule.

Clean shadow идёт до `H_target` eligible clusters либо до `D_max`, что наступит раньше. Если `D_max`
достигнут без required sample, verdict — **NO ARM / insufficient capacity or evidence**. Успешный PnL
не является причиной ранней остановки. Safety stop разрешён, но такой run не превращается в PASS.

## 5. Классификация критериев

| Критерий | Тип | Основание |
|---|---|---|
| абсолютный retained edge, а не только cohort gap | **hard / empirical** | passive control = -3.154 bp; `p × d` может быть мал |
| 5 s primary, 1/30 s sensitivity | **empirical + design choice** | coverage и existing decomposition |
| hour-cluster inference | **hard / statistical** | correlated fills, 30 clusters на 140 fills |
| fees и conservative funding/inventory bound | **hard / economic** | all-in edge, path dependence |
| exact action ledger укладывается в opening/marginal base и cancel allowances либо покупка явно разрешена | **hard / venue feasibility** | HL начисляет примерно одну base request на $1 cumulative volume, cancels имеют отдельный allowance, а дополнительные request weights можно купить |
| purchased-weight cost включена в absolute edge | **hard / economic** | `0.0005 USDC/weight`; при USDC≈USD один купленный weight на $1 filled notional ≈ 5 bp |
| normal-path maker-only | **hard / protocol invariant** | post-only strategy |
| frozen policy и no optional stopping | **hard / experimental integrity** | 840-trial selection и live recalibration history |
| zero safety invariant violations | **hard / money path** | real funds, fail-closed policy |
| `delta_econ = 1 bp` | **illustrative policy default** | operational margin; владелец должен подтвердить |
| zero purchased weights | **illustrative promotion policy** | позволяет сначала доказать устойчивость без платной capacity; это не venue invariant |
| join/markout coverage >=95% | **illustrative data-quality margin** | ограничение missingness bias |
| signal availability >=95% | **illustrative capacity margin** | signal, недоступный значительную часть времени, не является usable policy |
| actionability >=90% | **diagnostic default, не primary gate** | lead должен пережить tick + cancel latency; итог учитывается в net edge |
| 10–14 calendar days | **operational orientation** | weekday/weekend/regime coverage; final duration приходит из power plan |
| 50/400 fills, 60 clusters | **illustrative floors only** | rough iid math; заменить block-bootstrap result |

Нельзя silently повышать статус illustrative threshold до hard criterion. Любое такое решение
записывается до outcomes вместе с причиной.

## 6. Stage A — existing 36-fill directional triage

### 6.1 Цель

Не доказать tradeability, а решить, оправдана ли стоимость исправления state machine и нового shadow.

### 6.2 Data eligibility

- maker fills only; единственный taker разбирается отдельно;
- finite continuous `z`;
- `warm = true`;
- freshness и clock alignment проходят правило, записанное до join;
- nearest preceding shadow row, без look-ahead;
- join age и причины каждого exclusion публикуются;
- `raw_permit` не используется;
- sign фиксируется committed study;
- `half_life`, on/off thresholds и hysteresis фиксируются внешним immutable spec до outcomes.

Deployed `60 s / 4.0 / 1.5` из
[`bot-hype.toml`](../../../myhft-liqguard/deploy/hl-grid/bot-hype.toml) можно выбрать как policy, но
это post-study recalibration, а не threshold/window из committed study.

Знак фиксирован committed study:

```text
ask/sell fill: adverse_z =  z
bid/buy fill: adverse_z = -z
```

Fill-only nearest-z join проверяет только predictive direction. Для `p`, actionability, requests и
late-cancel-adjusted retained economics нужен полный timeline всех order-life intervals:
placement → первое threshold crossing → bot tick → cancel request → conservative venue arrival/ACK →
fill/cancel. Без этого policy economics остаётся optimistic diagnostic.

Stage-A report обязан посчитать `mu_all,overlap`, `p`, `d` и `mu_r` на одном eligible overlap, а
полный 140-fill control показать отдельно как representativeness check.

### 6.3 Outcomes

Используются три статуса:

**CONTINUE:**

- adverse-z slope имеет ожидаемый знак;
- high-adverse cohort хуже low-adverse cohort по point estimate;
- notional-weighted retained-policy point estimate после conservative late-cancel replay не ниже
  `delta_econ`;
- знаки slope и cohort difference сохраняются при leave-one-hour-cluster-out sensitivity.

**KILL:**

- `UCB95(retained_edge - blocked_edge) <= 0` на eligible sample; либо
- `UCB95(retained_edge) <= 0`; либо
- эффект имеет устойчиво неправильный знак на primary и sensitivity horizons.

**PARK / INCONCLUSIVE:**

- знак правильный, но CI слишком широк;
- cohort sample слишком мал;
- join/data quality не позволяет различить гипотезы.

`PARK` не разрешает clean shadow автоматически: владелец отдельно решает, стоит ли покупать
дополнительную информацию. `CONTINUE` не разрешает arm ни при каких значениях point estimate.

## 7. Stage B — binding clean-shadow gate

### 7.1 Preconditions

- flip accounting считает classifier transitions, а не verdict, форсированный guard'ом;
- gate-forced `Neither` не становится latch state (`#54`);
- writer/parser signal labels pinned одними golden vectors;
- policy config и commits immutable;
- inclusive-close fill/placement join D1 исправлен;
- out-of-window queue обозначается `NaN`, а не `0`;
- signal, order, ACK и fill clocks сведены и проверены;
- `sample_plan` создан до первого eligible tick.

### 7.2 Data-quality gate

Предлагаемые defaults, которые должны быть утверждены до запуска:

- signal→fill join coverage >=95%;
- 5 s markout coverage >=95%;
- signal availability >=95%;
- normal-path taker fills = 0;
- unresolved fee records = 0;
- every exclusion имеет machine-readable reason;
- missingness не имеет измеримой зависимости от `adverse_z`, side или markout activity.

Если missingness selective, высокий coverage сам по себе не спасает run: verdict — **NO ARM**.

### 7.3 Predictive mechanism gate

- `retained_edge - blocked_edge` имеет ожидаемый знак;
- `LCB95(retained_edge - blocked_edge) > 0`;
- adverse-z bucket curve не держится на одном cluster;
- sensitivity 1/30 s не показывает устойчивый сильный reversal.

Этот gate доказывает наличие signal mechanism, но не заменяет economic gate.

### 7.4 Economic gate

Одновременно:

```text
LCB95(retained_edge_5s_bps) > delta_econ_bps
```

и

```text
LCB95(expected_daily_retained_net_usd) > required_daily_profit_usd
```

Вторая строка требует заранее выбранного capacity target. Если target отсутствует, исследование может
доказать положительный edge, но не может назвать стратегию practically useful.

### 7.5 Actionability gate

Для каждого would-block fill строится timeline:

```text
signal threshold crossing
  -> bot decision
  -> cancel request
  -> conservative venue arrival / ACK
  -> fill
```

Основной способ учёта — не произвольный процент, а economics:

- fill, который не успевает отмениться при `p95` measured cancel latency + один bot tick, остаётся в
  policy losses;
- request overhead попадает в request gate;
- fill/cancel race публикуется отдельно.

Diagnostic default `actionable >=90%` можно оставить operational warning, но binding PASS всё равно
определяется net edge после late-cancel losses.

### 7.6 Request/capacity gate

`requests_per_filled_dollar` остаётся полезной диагностикой, но больше не является точной моделью
venue feasibility. Binding report строит timestamped ledger отдельно для:

- New/Create;
- Modify;
- Cancel и CancelAll;
- failed/retried actions;
- batch size: `n` orders/cancels = `n` address-based requests;
- opening earned headroom от historical cumulative volume как отдельный stock;
- marginal base allowance, заработанный retained volume текущего run;
- cancel allowance `min(limit + 100000, limit * 2)`;
- initial 10,000 buffer;
- reserved/purchased request weights;
- независимый high-congestion maker-share cap.

Публикуются два режима:

1. **Zero-purchase:** marginal steady-state ledger не требует reserved weights и не маскируется
   начальными 10,000 requests или historical headroom.
2. **Paid-capacity:** количество купленных weights умножается на текущую venue price и включается в
   `retained_edge_5s_bps` и daily net PnL. До outcomes фиксируются максимальная цена weight и hard
   daily/lifetime spend cap.

При текущей цене `0.0005 USDC/request weight`:

```text
purchased_weight_cost_bps =
    purchased_weights / retained_filled_notional_usd * 0.0005 * 10_000
```

При USDC≈USD один купленный weight на каждый доллар filled notional стоит около 5 bp. Promotion по
умолчанию предлагается сначала оценивать в zero-purchase режиме; разрешение платной capacity —
отдельный owner policy choice, а не способ скрыть отрицательный edge. Reserved weights снимают только
address-based cumulative cap и не считаются обходом независимого congestion cap. Актуальные venue contracts:
[rate limits](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/api/rate-limits-and-user-limits) и
[`reserveRequestWeight`](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/api/exchange-endpoint).

### 7.7 Operational integrity gate

- ноль flip-budget trips в normal data regime;
- ноль permanent/sticky `Neither`;
- outage требует re-warm;
- config/commit change обнуляет trial и требует нового experiment id;
- restart/outage handling следует заранее записанному правилу;
- ни один safety stop не преобразуется в statistical exclusion post hoc.

### 7.8 Stage-B verdict

**ARM CANDIDATE** — только если одновременно пройдены sample/power, data quality, predictive,
economic, actionability, request/capacity и operational gates.

**KILL `#20`** — mechanism или economic upper bound не достигает требуемого направления/margin на
достаточной выборке.

**NO ARM** — недостаточная capacity/data quality, safety stop или inconclusive к зафиксированному
deadline. Это не повод ретюнить thresholds на том же окне.

## 8. Code/safety gate перед физическим arm

Статистический `ARM CANDIDATE` ещё не разрешает изменение production config. До `mode = "armed"`
закрываются money-path blockers из
[`reviews/short-review-20260810.md`](../reviews/short-review-20260810.md) и signal design:

- совместимая, проверяемая пара bot/connector в release;
- operator credentials не попадают в release artifact;
- factual bounded startup reconciliation;
- resting orders отменяются при incomplete/one-sided book;
- partial-permit size clamp;
- correct leader depth freshness;
- hard loss, inventory, request и time stops;
- tested emergency flatten;
- signal mode/config явно присутствует в release manifest;
- rollback возвращает effective permit к `Both`/signal-disabled без оставшихся venue orders.

Любой незакрытый пункт = **NO ARM**, независимо от Sharpe, PnL или CI.

## 9. Stage C — minimum-size armed canary

### 9.1 Design

- HYPE как measurement laboratory;
- одна frozen geometry;
- minimum legal notional;
- один immutable build/config;
- fixed `H_target` и `D_max` из отдельного armed power plan;
- passive control не перезапускается: его absolute edge уже отрицателен;
- результат сравнивается прежде всего с zero/`delta_econ`, а historical passive используется только
  как context из-за regime drift.

### 9.2 Immediate safety stop

- reconciliation mismatch;
- normal-path taker fill;
- stale/incomplete book с оставшимися orders;
- signal state-machine invariant violation;
- lost/unattributed cancel;
- action ledger исчерпал разрешённый allowance либо пересёк configured purchased-weight spend cap;
- loss/inventory/liquidation bound;
- connector/bot version mismatch;
- funding/fee truth недоступна.

Safety stop завершает run как **STOP / NO SCALE**. Он не исключается из statistics и не рестартуется
под тем же experiment id до получения желаемого outcome.

### 9.3 Canary PASS

На actual armed path одновременно:

```text
LCB95(actual_net_edge_5s_bps) > delta_econ_bps
```

```text
LCB95(actual_daily_net_usd) > required_daily_profit_usd
```

а также:

- exact action ledger укладывается в утверждённые earned/cancel allowances и purchased-weight policy;
- fees/funding/inventory exact или fully reconciled;
- normal-path maker share = 100%;
- ни одного safety incident;
- результат не сосредоточен в одном cluster/regime.

Canary PASS разрешает только longer untouched OOS/canary. Немедленный size scale-up запрещён.

### 9.4 Canary KILL / NO SCALE

- `UCB95(actual_net_edge) <= delta_econ` на достаточной выборке: **KILL**;
- CI пересекает threshold к deadline: **NO SCALE / INCONCLUSIVE**;
- actionability/request/capacity failure: **KILL текущей implementation-policy pair**;
- safety failure: **STOP**, отдельный root-cause review до любого нового experiment.

## 12. Итоговая логика решения

```text
existing 36-fill join
  wrong sign with adequate evidence  -> KILL
  weak/inconclusive                  -> PARK / owner decides whether more data is worth buying
  correct and economically plausible -> clean frozen shadow

clean frozen shadow
  mechanism FAIL                    -> KILL #20
  economics/capacity FAIL           -> KILL or NO ARM
  data/safety FAIL                  -> NO ARM
  all gates PASS                    -> ARM CANDIDATE

code/safety review
  any blocker open                  -> NO ARM
  all blockers closed               -> minimum-size armed canary

armed canary
  actual absolute edge PASS         -> longer untouched OOS, no immediate scale
  economic FAIL                     -> KILL
  safety FAIL                       -> STOP and root-cause review
  inconclusive at deadline          -> NO SCALE
```

Главный принцип: сигнал продвигается не потому, что он «правильно предсказывает» и не потому, что
blocked fills выглядят хуже. Он продвигается только если frozen policy после реальной задержки и всех
costs создаёт достаточный **абсолютный** edge на независимых временных блоках и проходит money-path
safety gate.
