## 0. Термины, единицы, общая измерительная рамка

**Ячейка (cell)** = пара `(venue, symbol)`, оценённая на пуле дней окна W (§4).
Кросс-венью пулинг запрещён. Все критерии окна и включения — **per-cell**;
формулировки «площадка целиком» ниже — shorthand для «все её ячейки»
`[panel: goodhart-m2]`.

**Trade-time.** `t` — счётчик **маркет-ордеров** (кн. с. 187; формат
trades-and-quotes и необходимость склейки принтов — кн. с. 213: «Trades-and-quotes
data sets typically report such activity as different, successive transactions
with identical or very similar time stamps» `[panel: math-m4]`).

**Единицы.** Все ценовые величины — в bps относительно мида перед сделкой.
Формулы книги однородны по цене, переход законен.

| Символ | Определение | Единицы |
|---|---|---|
| `ε_t` | знак t-го маркет-ордера: `+1` тейкер купил, `−1` продал | — |
| `ε̄` | среднее `ε_t` по ячейке; печатается всегда | — |
| `m_t` | мид непосредственно перед приходом t-го маркет-ордера | цена |
| `b_t`, `a_t` | лучшие бид/аск того же кадра | цена |
| `x_{t,ℓ}` | `1e4 · (m_{t+ℓ} − m_t) / m_t` | bps |
| `s_t` | `1e4 · (a_t − b_t) / m_t` | bps |
| `s̄` | `mean_t s_t` (trade-time weighted) | bps |
| `⟨s²⟩` | `mean_t s_t²` (trade-time) — знаменатель `rho_val`, §3 | bps² |
| `C(ℓ)` | `mean[ε_t ε_{t+ℓ}] − ε̄²` (ковариация) | — |
| `R(ℓ)` | `mean[ε_t · x_{t,ℓ}] − ε̄ · mean[x_{t,ℓ}]` (**ковариационная форма**, `[panel: math-M3, stats-m2]`; сырая форма печатается рядом) | bps |
| `R_inf` | `mean_{ℓ=20..50} R(ℓ)` на **общем поднаборе пар** (§1.6) | bps |
| `C̄_plateau` | `mean_{ℓ=20..50} C(ℓ)` на том же поднаборе | — |
| `M_null` | `(s̄/2) · C̄_plateau` — **MRR-нуль усечения**, §2 `[panel: math-C3]` | bps |
| `σ̃²(20)` | `Var[x_{t,20}] / 20` на том же поднаборе | bps² |
| `fee_v` | мейкер-комиссия, за одну сторону; «+» платим, «−» ребейт | bps |
| `s_eff` | `s̄ − 2·fee_v` (книжное `s + 2ϖ` при `ϖ = −fee_v`) | bps |

**Почему `R(ℓ)` центрируется.** Книга строит гл. 17 на допущении `E[ε] = 0`
(кн. с. 324); у нас `ε̄` до 0.32 (NEAR 0808, MEASURED
`probe_hl_multi_0808.txt`), и нецентрированная форма несёт дрейф `ε̄·E[x_ℓ]`
(на HYPE: +3.8% от `R_inf` при ℓ=50, +22% при ℓ=500). Эффект на плато 20..50
измерен ≤5% (`mrr_probe2.py`), но асимметрия «C центрирован, R нет» — разные
объекты при `ε̄ ≠ 0`. Обе формы печатаются; решает ковариационная. При
`|ε̄| > 0.15` ставится флаг `EPS_DRIFT` (направленный день/пул; предпосылка
книги нарушена — чтение ячейки с оговоркой).

**Почему `s̄` — среднее по сделкам.** Кн. Table 11.1 (с. 214), Eq (17.15) —
на нём. Старый time-weighted спред оптимистичен 1.41–2× (память
`project_no-viable-cell.md`).

### 1.3 Определение сделки: маркет-ордер, а не принт

Агрегируем принты в маркет-ордера. Обоснование: Eq (16.22)/(17.15) записаны на
знаках маркет-ордеров (кн. с. 187, с. 213); свип из K принтов механически
завышает `C(1)` и занижает `R(1)` — смещает оба входа в сторону «торговать
можно». MEASURED-подтверждение самой агрегации: HL HYPE без агрегации
`C(1) = 0.515`, с агрегацией ≈ 0.07 (`probe_takerkey_hl_hype_0808.txt`).

Ключ агрегации — строго по площадке, из §10. Общая форма:
`order_key(print) = (venue_specific_key, sign)`; принты с одинаковым ключом,
идущие **подряд** в порядке биржевого времени, склеиваются. Атрибуты:
`sign`; `t_ex` = минимальный биржевой ts принтов; `t_local` = **receive-ts
первого принта** (для правил §1.5–1.6) `[panel: impl-C2]`; `qty`, `n_prints` —
в отчёт.

Ключ, собравший оба знака, разбивается по знаку. Сортировка ордеров — по
`(t_ex, порядок появления в файле)`, стабильная. `[panel: math-m2]` Тай-брейк
load-bearing (MEASURED: сортировка равных ms по `(t, знак)` вместо стабильной
сдвигает HYPE `C(1)` на 0.024 — 200% самой оценки): в TDD-набор `mrr_gate.py`
входит **тест на стабильность сортировки**; в `cells.json` печатается
`frac_orders_sharing_ms` (при ms-часах истинный порядок невосстановим — это
записанное ограничение точности `C(1)`).

### 1.5 Мид и спред: `m_t`, `b_t`, `a_t`, `s̄` — правило живости вместо возраста

Источник тача — строго один на площадку (§10). Смешивать внутри ячейки
запрещено.

Для ордера `t` берётся последний кадр тача с биржевым ts **строго меньше**
`t_ex(t)`.

`[panel: math-C1, impl-M6, stats-M2]` **Возрастного лимита кадра больше нет.**
v0.1 выбрасывала ордер, если кадр старше 2 с; на событийных фидах (HL `bbo`
публикуется на смену BBO; p90 межкадрового интервала у неликвидов 2.7–6.8 с,
MEASURED `probe_bbo_cadence_hl_0808.txt`) это читало тихий рынок как отсутствие
данных и в одиночку выносило 13 из 16 контрольных ячеек. Порог 2.0 с к тому же
стоял в теле распределения (p99 возраста тача HYPE = 1.8 с) и был самой мощной
незамеренной ручкой спеки (±1 с переворачивал включение hype/pump в обе
стороны, MEASURED `stale_sensitivity.jsonl`).

Ордер **выбрасывается из мид-зависимых статистик** (не из знаковой цепочки),
если выполняется любое из:

1. валидного кадра строго-раньше нет вовсе (начало дня/цепочки);
2. в кадре не выполняется `0 < bid < ask`;
3. **фид мёртв**: между кадром и ордером в тач-потоке есть разрыв приёма
   `> TOUCH_DEAD_S = 60 с` (по локальному ns-приёму тач-кадров), либо в
   `_meta_<venue>_<date>.jsonl` в этом интервале записан реконнект. Тишина
   события ≠ смерть фида: последний кадр событийного фида — актуальный тач.

`[panel: math-C1(б), stats-M2]` **Выброшенный ордер НЕ рвёт цепочку.** Его `ε`
остаётся в знаковой последовательности (для `C(ℓ)` мид не нужен); из `R(ℓ)`,
`s̄`, `σ̃²` исключаются только **пары с его участием**. (v0.1 рвала цепочку —
при p=10% дропов вероятность цепочки ≥500 была `(1−p)^500 < 1e-22`, что и
блокировало контроль.) Доля выброшенных печатается; `> MAX_DROPPED_FRACTION =
0.10` (по новому, liveness-определению) → `EXCLUDED (STALE_QUOTES)`.

`m_t = (a_t + b_t)/2`; `s_t`, `s̄`, `⟨s²⟩` — по ордерам с валидным мидом.
В отчёт дополнительно: `s_p25_tradetime`, `s_p50_tradetime`,
`s_p50_timeweighted` (непрерывность старого ряда, §7), `CV_s = std(s_t)/s̄`
`[panel: math-M2]`.

`[panel: math-M4]` **Классификация тика.** Per-cell печатаются `tick`
(минимальный положительный спред за пул), `s_bar_ticks = s̄/tick`,
`P[s = 1 tick]`. При `P[s = 1 tick] > LARGE_TICK_P1 = 0.5` — флаг `LARGE_TICK`:
книга прямо объявляет Eq (17.12)–(17.15) неприменимыми к large-tick (Fig 17.1
подпись, кн. с. 327; сноска 3 с. 322; §17.3 даёт формулу только для головы
очереди). Ячейка с `LARGE_TICK` читается (PASS/FAIL по существу), но **не
промоутится**: её `PASS` верен только «при приоритете в голове очереди», чего
скрин не измеряет. MEASURED: HYPE `P[s=1 тик] = 0.883`, PUMP 0.769
(`probe_ticks_hl_0808.txt`) — наш флагман сидит в этом режиме.

### 1.6 Цепочки, разрывы и оценщики `C(ℓ)`, `R(ℓ)`, `R_inf`

Цепочка рвётся **только**:

1. на границе суточного файла;
2. при разрыве приёма `> GAP_BREAK_S = 60 с` между соседними ордерами
   (по `t_local`);
3. на границе непригодного дня (§4.2).

(Пункт v0.1 «при выброшенном ордере» удалён — см. §1.5.)

Пары `(t, t+ℓ)` — только внутри цепочки.

`[panel: stats-M4]` **Общий поднабор пар для плато.** Все плато-статистики —
`C(20..50)`, `R(20..50)`, `R_inf`, `C̄_plateau`, `R_flatness`, `σ̃²(20)` —
считаются на **одном** множестве базовых индексов: `t` таких, что `t` и `t+50`
лежат в одной цепочке и оба конца каждой пары `t..t+ℓ` имеют валидный мид.
Иначе `R(20)` и `R(50)` считаются на разных популяциях (MEASURED: jto 0808 —
237 пар на ℓ=20 против 38 на ℓ=50; «плато» на неликвиде меряло дрейф busiest-
эпизодов: средний `x` подвыборки ℓ=50 = +9.0 bps у crv). `n_pairs` печатается
**на каждый лаг**; по построению на плато он одинаков.
`n_pairs(50) < MIN_PAIRS_PLATEAU = 1000` → `EXCLUDED (INSUFFICIENT_PAIRS)`.
`[panel: goodhart-M3]` Любая нефинитная статистика (NaN/Inf, пустое множество
пар) → `EXCLUDED (ESTIMATOR_UNDEFINED)`; сравнение с NaN не «False», а код.

```python
eps_bar = mean(all eps)                              # по всей ячейке
C[l]    = mean(eps[t]*eps[t+l]) - eps_bar**2         # общий поднабор для 20..50
R[l]    = mean(eps[t]*x[t,l]) - eps_bar*mean(x[t,l]) # ковариационная форма
R_inf   = mean(R[l] for l in 20..50)
M_null  = (s_bar/2) * mean(C[l] for l in 20..50)
```

Печатаются также: сырая `R_raw(ℓ) = mean(ε·x)`, `E[x_ℓ]` для ℓ ∈ {20, 50}
(след дрейфа), `R̂∞_1622 = mean_ℓ R(ℓ)/(1−C(ℓ))` (оценщик Eq 16.22, под MRR
несмещённый; MEASURED HYPE 0.604 против 0.585 сырого плато) `[panel: math-C3(б)]`.

**Плоскость и рост.** `R_flatness = |R(50) − R(20)|/|R_inf|` на общем
поднаборе; `> 0.25` → флаг `R_INF_UNRESOLVED`, PASS невозможен (fail closed).

`[panel: math-C3(в), в изменённом виде]` **Тест роста по декаде.** На парах,
где `t` и `t+200` в одной цепочке (свой поднабор, свой `n_pairs`):
`R_growth = R(200)/R(50) − 1`. Если `R_growth > R_GROWTH_MAX = 0.25` — флаг
`R_GROWTH`: измерен режим `β < β_c`, в котором `R(ℓ)` уходит вверх без плато
(кн. Eq 13.18 с. 258; гл. 17 с. 322: «If β < (1−γ)/2 … R(ℓ) instead diverges
to +∞, rendering market-making extremely difficult»). Это **не** «неустановленный
R_inf», а содержательный вердикт: *пассивное котирование здесь невозможно*;
флаг запрещает PASS и усиливает чтение FAIL. MEASURED: HL HYPE `R(50)=0.638 →
R(200)=0.753 → R(500)=0.987 → R(2000)=1.891` — плоскость v0.1 (`flat=0.191`,
проходил) сертифицировала плато, которого нет. **PASS требует, чтобы тест роста
был вычислим** (`n_pairs(200) ≥ MIN_PAIRS_PLATEAU`) и пройден; невычислимость
блокирует только PASS, не FAIL/EXCLUDED.

`[panel: math-C4(б), stats-m3]` **Знаковая структура.** Гейт целостности:
`C(1) > 0` **и** `C̄_plateau ≤ C(1)` — иначе `EXCLUDED (SIGN_STRUCTURE)`.
Книга (гл. 10, Table 11.2) — `C(ℓ)` строго положительна и медленно затухает;
`C(1) ≤ 0` — сигнал неисправного оценщика (вырожденный ключ агрегации,
неправильные часы), а не свойство рынка. Дополнительно печатается `C(1)` **без
агрегации** — и в §2 записано: при `|C(1)| < 0.05` разделение
быстрый/терпеливый вырождается (`M_fast ≈ M_patient` с точностью до горизонта
`R`), чтение «здесь зарабатывает кто-то быстрее нас» не обосновано.

## 2. Два условия гейта

`s_eff = s̄ − 2·fee_v` (кн. с. 322/326: «for ϖ ≠ 0 one simply needs to replace
s by s + 2ϖ»).

**Условие 1 — быстрый мейкер** (Eq 17.14/17.15, предел `α → 0`):
`M_fast = s_eff·(1 − C(1))/2 − R(1)`.

**Условие 2 — терпеливый мейкер** (Eq 17.3/17.13, предел `α → 1`):
`M_patient = s_eff/2 − R_inf`.

`[panel: math-M7]` **Почему решает терпеливое условие — исправленное
обоснование.** v0.1 обосновывала выбор латентностью (607 мс) — это подмена
смысла: `α = 1 − κυ₀` (Eq 17.5–17.6) — скорость **инвентарной** мин-реверсии,
а не скорость реакции, и предел `α → 1` — отсутствие инвентарного контроля
(`V[ψ] → ∞`, Eq 17.7), которое наш риск-стек (#43) запрещает. Правильное
обоснование: Fig 17.1 (кн. с. 327) показывает P&L мейкера **монотонно
ухудшающимся с ростом α** на всех четырёх бумагах — терпеливый предел есть
**нижняя граница семейства (17.12)**, и гейт по нему пессимистичен по
построению. MEASURED-подтверждение: `M_fast > M_patient` на всех 11 измеримых
HL-ячейках. (Промежуточное `α` — вне scope, §13 и §17-R4.)

- `PASS` присуждается только по `M_patient` (вместе с §3, §4, §6);
- `M_fast` печатается всегда — чтение, не право торговать;
- `[panel: math-M1]` **режимные метки вместо «неполадки»:**
  `M_fast > 0 ≥ M_patient` → `regime: "fast_only"` («здесь зарабатывает
  кто-то быстрее нас») — не промоутится;
  `M_patient > 0 ≥ M_fast` → `regime: "slow_only"` — **легитимный режим, а не
  сигнал бага**: на самой Fig 17.2 (кн. с. 328) между линиями подписана область
  «Slow MM profitable», совпадают линии только в точном MRR, а гейт и меряет
  отклонение от MRR. Промоутится наравне с прочими PASS. Ручная перепроверка
  v0.1 удалена (заодно закрыт escape hatch — §17-R7 / goodhart-m5).

**Правило решения (fail closed):**

```
PASS  ⇔  LB_{1 − ALPHA_FAMILY/K}(M_patient − M_null) > 0
         ∧ медиана по дням точечной M_patient > M_null
         ∧ нет блокирующих флагов
```

где:

- `[panel: math-C3(а)]` **`M_null = (s̄/2)·C̄_plateau` — MRR-нуль усечения, а
  не ноль.** Под MRR `R_∞ = s/2` тождественно (кн. с. 310), и усечение плато на
  конечном ℓ даёт `M_patient = (s/2)·C̄(ℓ) > 0` строго — при `fee = 0`
  (заявленная строка lighter) порог «> 0» пропускал бы артефакт усечения.
  MEASURED масштаб: +0.37 bps (KAITO), +0.23 (PUMP) — ровно там, где решается
  вердикт. Бутстрапится напрямую разность `D = M_patient − M_null` (обе — 
  статистики реплики).
- `[panel: stats-C4, goodhart-M1]` **Поправка множественности:** `K` = число
  не-EXCLUDED ячеек прогона; LB берётся перцентилем уровня
  `1 − 0.05/K` бутстрап-распределения `D` (одношаговый Бонферрони; он
  консервативнее Холма — допустимое fail-closed упрощение, зафиксировано).
  MEASURED-масштаб проблемы: 82 ячейки-кандидата на шести площадках; без
  поправки ожидаемые ложные PASS были бы уже на первом скрине.
- `[panel: stats-M5, в изменённом виде]` **Согласие знака по дням:**
  невзвешенная медиана по дням точечной `M_patient` обязана превышать `M_null`
  пула. Взвешенный пул и помесячная разница печатаются (MEASURED: `pooled −
  day_median` до ±2.1 bps на контроле — произвол масштаба решения). Доля одного
  дня в ордерах ячейки `> DAY_SHARE_MAX = 0.25` → флаг `DAY_CONCENTRATION`,
  блокирует PASS.
- **Блокирующие PASS флаги:** `R_INF_UNRESOLVED`, `R_GROWTH` (или его
  невычислимость), `CI_UNCONVERGED`, `CI_UNAVAILABLE`, `DAY_CONCENTRATION`.
  `LARGE_TICK` и `EPS_DRIFT` не блокируют PASS, но `LARGE_TICK` блокирует
  промоушен (§1.5).
- `[panel: goodhart-M1]` **Репликация:** первый PASS ячейки печатается как
  `PASS_UNREPLICATED` и **не промоутится**. Промоушен — только после PASS на
  **двух окнах без общих дней** (при недельном каденсе и 10-дневном окне это
  скрины с разницей ≥ 2 недель). В `cells.json` — поле `n_screen_attempts`.

Точечная `M_patient > M_null` при недостаточном LB — `FAIL` с флагом
`marginal: true`.

## 3. Валидационный гейт целостности — Fig 16.4 вместо полосы `rho_val`

`[panel: math-C2, stats-M1]` **Центральное изменение против v0.1.** Полоса
`rho_val ∈ [0.25, 4.0]` (Eq 16.23) оказалась не детектором багов, а детектором

связь волатильность-спред **насыщается** (кн. с. 214, п. (ii) — large-tick);
плюс дисперсия мида у нас создаётся переоценкой котировок между сделками
(5.27 кадра bbo на ордер, MEASURED `variance_decomp.jsonl`), чего Eq 16.23 не
описывает. При этом лаг-1 MRR-соотношение на той же ленте **выполняется**.

**Гейт целостности заморожен по Fig 16.4** (кн. с. 313: «The average spread
versus 2R(1)/(1−C(1)) … The dashed line y = x is the MRR prediction»):

```
response_ratio = 2·R(1) / ((1 − C(1)) · s̄)
Гейт: response_ratio ∈ RESPONSE_BAND = (0.4, 2.5)
```

Вне полосы → `EXCLUDED (RESPONSE_SPREAD_BAND)`. Что ловится: перепутанные
единицы времени (×10³), недедуплицированный реплей, выравнивание не по тем
часам, вырожденный ключ агрегации, спред не с той стороны — всё уводит

§5.5, двигаются только до заморозки.

Второй гейт целостности — **at-touch предикат** (кн. с. 213: «exact match
between the transaction price and either the bid- or the ask-price»):
`frac_at_touch` = доля ордеров, чей первый принт стоит ровно на биде/аске
кадра-перед-ордером. MEASURED HYPE: 0.959 (ключ тейкера). Гейт:
`frac_at_touch ≥ AT_TOUCH_MIN = 0.80`, иначе `EXCLUDED (TOUCH_MISMATCH)`.
Это и есть прямой детектор «реконструктор/часы отдают не тот тач», которым

**`rho_val` остаётся печатью, а не вердиктом** — и в исправленной форме:
`rho_val = σ̃²₂₀ / (⟨s²⟩·(1 − C(1)²)/4)` — знаменатель `⟨s²⟩` (trade-time),

сделку» — это **содержание** (аргумент к FAIL), а не нечитаемость.

4. доля мид-выброшенных ордеров `≤ 0.10` (liveness-правило §1.5) → иначе
   `STALE_QUOTES`;
5. `response_ratio ∈ (0.4, 2.5)` → иначе `RESPONSE_SPREAD_BAND`;
6. `frac_at_touch ≥ 0.80` → иначе `TOUCH_MISMATCH`;
7. `C(1) > 0` и `C̄_plateau ≤ C(1)` → иначе `SIGN_STRUCTURE`;
8. все статистики финитны → иначе `ESTIMATOR_UNDEFINED`;
9. строка `fee_v` заполнена → иначе `FEE_UNKNOWN`;
10. знаковая конвенция верифицирована (§1.4) → иначе `SIGN_UNVERIFIED`.

`bootstrap_coverage` критерием больше **не** является (§1.8). Ёмкостный
ко-гейт (§6) — условие промоушена, не включения.

11. **`[post-panel, из wf-arb4 2026-08-11]` RFQ/индикативные рынки исключаются
    по флагу площадки ДО всякой арифметики** → `RFQ_MARKET`. Основание
    (MEASURED, wf-arb4-freshvenue): у extended `isRfq == true` на **231 из
    344** рынков; на RFQ-рынке `/orderbooks` отдаёт **индикативную** книгу
    (doc-комментарий нашего же `collector/src/extended/mod.rs:38-40`), 87–90 %
    принтов ложатся строго внутрь записанного best bid/ask — «спред» не
    является ценой исполнения. Калибровочный факт: старый скрин
    `p25 > 2×fee` поставил бы extended JTO-USD (p25 ≈ 148 bps, maker 0)
    **первым номером всего обзора**. Реализация: перед включением ячейки
    extended исполнитель обязан свериться с `markets`-снапшотом площадки и
    выбросить `isRfq == true`; для остальных площадок аналогичный флаг —
    если существует — проверяется тем же правилом. Добавлено после панели,
    до заморозки; статус — на утверждении оператора вместе с остальным.

## 9. Семантика вердиктов

### 9.1 Четыре исхода

| Вердикт | Когда | Что делать |
|---|---|---|
| **PASS** | §4.3 выполнен, §3 пройден, правило §2 выполнено | первый раз — `PASS_UNREPLICATED`, промоушен только после репликации (§2) + §6 + §8 + отсутствие `LARGE_TICK` |
| **FAIL** | §4.3 выполнен, §3 пройден, правило §2 не выполнено | результат, идёт в ряд; `marginal: true`, если точечная `M_patient > M_null` |
| **EXCLUDED** | нарушен любой критерий §4.3 | НЕ ЧИТАЕТСЯ ни в какую сторону |
| **FAST KILL** | §9.2 | запечатывается |

Флаги (`R_INF_UNRESOLVED`, `R_GROWTH`, `CI_UNCONVERGED`, `CI_UNAVAILABLE`,
`DAY_CONCENTRATION`, `LARGE_TICK`, `EPS_DRIFT`) — не вердикты; их действие
описано в §1.5–1.8, §2.

### 9.2 FAST KILL — два уровня

**Ячейковый.** `[panel: stats-M7]` Запечатывание — необратимое отрицательное
решение, и его fail-closed смотрит в другую сторону, чем PASS. Требования:
`N_orders ≥ 30 000`; `n_pairs(50) ≥ MIN_PAIRS_PLATEAU`; **нет**
`R_INF_UNRESOLVED`/`CI_UNCONVERGED`/`CI_UNAVAILABLE`; и `UB95(M_patient_best)
< 0`, где `M_patient_best = s_eff/2 − min_{ℓ∈20..50} R(ℓ)` — самый
благоприятный допустимый `R_inf`. Ошибка ведёт к «перемерим ещё раз», а не к
«убили живую ячейку». Запечатанные — в `REPORTS_DIR/sealed-cells.json`
(персистентный каталог, §11); разпечатывание — только материальное изменение
(тариф, тик/лот, листинг, механика).

**Программный.** `[panel: impl-m4, goodhart-M6, stats-C4]`
`FASTKILL_PROGRAM_N = 8` (было 30 — недостижимо: включённых ячеек 16.08
ожидается ~5–8, и «kill не сработал» был бы неотличим от «kill не мог
сработать»). Правило: включено ≥ 8 ячеек, контроль пройден, `max` точечной
`M_patient` по включённым `< −1.0 bps` → FAST KILL программы (следующий шаг
структурный, не ещё один скрин). При `included < 8` в `summary.md` печатается
**явное** `program_kill: NOT_EVALUABLE`.

### 9.3 Коды `EXCLUDED` (закрытый список)

```
WINDOW_COVERAGE       < 5 пригодных будних дней (per-cell)
INSUFFICIENT_N        < 10 000 агрегированных ордеров
INSUFFICIENT_PAIRS    < 1 000 пар на l=50 в общем поднаборе
STALE_QUOTES          > 10% ордеров без валидного мида (liveness-правило §1.5)
RESPONSE_SPREAD_BAND  2R(1)/((1-C(1))*s̄) вне (0.4, 2.5)
TOUCH_MISMATCH        frac_at_touch < 0.80
SIGN_STRUCTURE        C(1) <= 0 либо C̄_plateau > C(1)
ESTIMATOR_UNDEFINED   нефинитная статистика / пустое множество пар
FEE_UNKNOWN           строка комиссии не заполнена/не подтверждена
SIGN_UNVERIFIED       конвенция знака не верифицирована (§1.4)
PARSE_ERROR           структурная ошибка чтения, ячейка не собрана
```

Ячейка с несколькими причинами печатает все.

### 9.4 Что вердикт означает и не означает

- `PASS` не означает «торговать прибыльно»: без инвентарного риска, латентности,
  проигрыша очереди, фандинга; adverse на нашем реальном расстоянии (#32/#57)
  — вне формулы.
- `[panel: math-M6]` **Что `M_patient` измеряет на самом деле:** сноска 8
  кн. с. 310 — MRR с order-processing cost `c` даёт `s = 2(G* + c)`, то есть
  под точным MRR-с-издержками `M_patient = s/2 − R_∞ = c > 0` **всегда**.
  `M_patient − fee_v > 0` читается буквально как «наша комиссия ниже суммарной
  издержки маргинального инкумбента», а не «здесь есть альфа». Это чтение
  делает гейт осмысленным (и объясняет, почему нулевая комиссия — единственный
  реалистичный источник PASS) — и запрещает переоценивать любой PASS.
- `[panel: math-M5]` **Безусловная `R(ℓ)` — верхняя граница выгодности для
  мейкера:** `R_φ(ℓ)` возрастает по φ (Eq 17.16, кн. с. 329), откуда строго
  `E[G^random] < E[θ]·E[G^top]` — маркет-ордера, в которых участвуем мы,
  информированнее среднего. Оба усечения (это и `M_null`) смотрят в сторону
  PASS — поэтому оба закрыты явно (§2, диагностика `R¹(1)` в §3).
- `FAIL` означает ровно то, что написано; с флагом `R_GROWTH` — сильнее:
  измерен режим, в котором книга называет маркет-мейкинг «extremely difficult».
- `EXCLUDED` не интерпретируется никак.

## 17. Отклонённые возражения (с обоснованиями)

**R1. [stats-C2, часть] «`R_inf/R(1) ∈ [2,5]` — гейт, а не печать».**
Отклонено. Та же линза измерила 8/16 заведомо здоровых контрольных ячеек вне
диапазона (sui 7.9, aero 9.0, crv 9.4), а math-линза — наш диапазон 2.6–7.3
при книжном «эмпирическом 2–5». Гейт на этой диагностике воспроизвёл бы ровно
ту самоблокировку, которую панель сняла с полосы `rho_val`. Невырожденность
`R_inf` закрывается иначе: plant (§5.2.4), `SIGN_STRUCTURE`, `R_GROWTH`,
`R_INF_UNRESOLVED`. Диагностика печатается.

**R2. [math-C1, альтернатива (а)] «взять для HL `l2Book` как тач».**
Отклонено в пользу `bbo` + liveness-правила (§1.5). `l2Book` — ~2 кадра/с
против медианы 0.14 с у `bbo`: систематически более старый `m_t` перед каждым
ордером ухудшает точность `R(1)` и at-touch ровно там, где решается `M_fast` и
предикат §3. Корневая причина (чтение событийной тишины как протухания)
устранена напрямую; смена тач-источника чинила бы симптом ценой разрешения.

**R3. [math-C3, вариант (в) буквально] «MAX_LAG поднять до 500–2000».**
Применено в изменённом виде, буквальная форма отклонена. Плато решения остаётся
20..50: (а) сопоставимость с постановкой #71 и с контролем #57; (б) на тонких
ячейках пар на ℓ=2000 нет — требование сделало бы `R_inf` невычислимым ровно
там, где скрин ищет кандидатов, воспроизведя самоблокировку. Рост ловится
декадным тестом 50→200 (`R_GROWTH`, §1.6) с книжным чтением β<βc; смещение
усечения нейтрализуется порогом `M_null` (§2). Вместе они закрывают то, ради
чего предлагался длинный лаг, без потери вычислимости.

**R4. [math-M7, добавка] «промежуточное `α` по Eq (17.12) посчитать — держать
вне scope дороже».** Отклонено (YAGNI, AGENTS.md §1.2). Fig 17.1 показывает
монотонность P&L по α — терпеливый предел уже нижняя граница семейства, и
решение гейта от промежуточного α не меняется ни в одном исходе: PASS по
нижней границе влечёт PASS всего семейства, FAIL по ней читается как FAIL
пессимистичной кромки, что и заявлено. Третий оценщик в неделю заморозки — 
поверхность для ошибок без изменения решений. Кандидат в v0.2 вместе с wave-2.

**R5. [stats-M5, первичная часть] «решает невзвешенная медиана по дням».**
Применено как ко-условие, первичность отклонена. Per-day `M_patient` требует
per-day `R_inf`; при пороге дня в 200 ордеров это оценка на сотнях пар — шум,
переодетый робастностью (сама линза измерила `C(50)` на 987 парах с ошибкой
знака). Медиана пяти шумных чисел не несёт CI, а PASS определён через LB.
Поэтому: решает пул (у него есть бутстрап), медиана по дням — обязательное
согласие знака, концентрация дня — флаг `DAY_CONCENTRATION` (§2). Оба числа
печатаются.

**R6. [stats-C4 / impl-m4, альтернатива] «программный kill как доля: ≥80%
включённых с UB95 < 0».** Отклонено в пользу N=8 + `NOT_EVALUABLE`. Форма-доля
молча меняет семантику предрегистрированной остановки (максимум точечной
`M_patient < −1 bps` — «даже лучшая ячейка глубоко мертва») на другую
(«большинство ячеек уверенно мертво»), а UB-зависимость подвешивает
необратимое программное решение на бутстрап, который §1.8 сам объявляет
несошедшимся на нашем флагмане. Сохранена исходная семантика, исправлена
достижимость; смена N — операторский пункт §14.6.

**R7. [goodhart-m5] «ячейка `M_patient > 0 ≥ M_fast` не промоутится
безусловно; перепроверка = записка + v0.2».** Отклонено как superseded:
math-M1 показала, что сам диагноз «неполадка» в v0.1 был ошибкой чтения
Fig 17.2 (область «Slow MM profitable» подписана на самой фигуре). Ручной
перепроверки больше не существует — вместе с ней исчез и escape hatch, на
который указывала находка: режим `slow_only` промоутится по общим правилам
(§2), без человеческого суждения в контуре. Цель находки (убрать
недетерминированное право промоутить) достигнута сильнейшим способом.

**R8. [stats-M6, часть] «`fee_v` заморозить сегодня худшим публичным числом с
URL».** Отклонено в буквальной форме: строка комиссии, вписанная агентом без
проверяемого источника, — ровно та «строка без источника», которую §1.9
запрещает. Механизм спеки уже fail-closed (нет источника → `FEE_UNKNOWN`,
площадка не читается — щедрых допущений нет); заполнение строк оставлено
оператору/исполнителю с дедлайном 13.08 (§14.1). Направление находки (не дать
комиссии остаться свободным параметром) выполнено самим `FEE_UNKNOWN`.
