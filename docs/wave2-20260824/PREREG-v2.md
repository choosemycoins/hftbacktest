## 2. Часы, события, цель

**Объект → часы:** знаковый ряд и ядро — событийное время (тики агрессий);
LM, rv, |Δ1s|, горизонты — настенные секунды; состояния K2/K3 — настенные окна
на барах. Выбор окончательный.

**Агрессия** = группа tid с одинаковыми (venue-ts мс, coin, side); объём = Σ sz;
один тик часов, одно событие, один вес. Единообразно всюду.

**Событие-носитель:** агрессия с принтом at/through тача. Тач = последний кадр
bbo с локальным приёмом строго раньше локального приёма принта (assert; джиттер
транзита ~204 мс — объявленное свойство прибора).

**Цель:** y = side-adjusted лог-ход мида HL от последнего пред-событийного кадра
bbo на горизонте h; первичный h = 1 с; вторичные 2/5/10 с. **Purge:** keep-first
по 1-с окну; вторичные горизонты — на той же популяции, точечно, без CI,
непромоутяще.

## 3. Именованный оценщик: DAR-сюрприз

1. ε_t ∈ {−1,+1} по агрессиям (конвенция users); w_t = ε_t·log(1+v_t/v̄),
   v̄ = медиана объёма агрессии окна оценки ядра.
2. C(ℓ), ℓ=1…50 тиков агрессий; настенный размах 50 тиков печатается по символам
   (объявленное свойство). Недокондиционирование ловит канарейка OFI (§5, §10).
3. **Окно оценки ядра:** трейлинг по квалифицированным суткам, конкатенация,
   **растёт назад до n ≥ 15 000 агрессий, потолок 7 суток**; при недостижении —
   ячейка выбывает поимённо. Сутки, провалившие гейт §1, окном служить не могут.
   Фактическое n окна каждой ячейки — в инвентарь §11.1.
4. Walk-forward — структурные ассерты на КАЖДОЕ трейлинг-окно (ядро, v̄, β, σ_z,
   EWMA, rv): max(ts входов) < ts события.
5. s_t = ε_t − Σ K(k)ε_{t−k}; s^v_t — из w_t. Первые 50 событий суток берут лаги
   из хвоста окна оценки.

## 4. Кондиционирующий стек

basis-z: b_t = log(mid_HL/mid_BN), z_w = (b_t − EWMA_w(b))/EWSD_w(b), в стек w=30 с
(5/120 с — отчётно). Сюрприз s_t (s^v_t — отчётно). Волатильность: |Δ log-mid HL
за [t−1 с, t)| — ось стек-ячеек §6; трейлинг-rv 60 с кондиционирует через
вторичные оценщики §6 (OLS/регрессия) и анти-плант. (Поправка v2.2: формула
ячеек §6 авторитетна; рассинхрон §4/§6 пойман анти-плантом rv = 0.074.)

## 6. Решающая статистика

**I(кандидат, символ) := ½·(E[y|D10] − E[y|D1])**: децили кандидата внутри
стек-ячеек (квинтиль z30 × терциль s_t × терциль |Δ1s|; ранги пулируются), на
1-с-прореженной популяции; вес события 1 (нотионал — отчётно). CI — кластерный
бутстрап по суткам.

**Пулы по кандидатам (составы — имена заморожены):**
* POOL-K1, POOL-K2 = равновзвешенное среднее ROW по 15 не-HYPE символам;
* POOL-K3 = равновзвешенное по 8 символам с ногой;
* ROW-HYPE — отдельная отчётная строка (только денежная конвертация).

**Вторичные оценщики (формулы):** (i) OLS-рез.: y_res = y − ŷ, ŷ — линейная OLS
y на [z30, s_t, rv60, |Δ1s|] по символу на событийных сутках; I = децильный
контраст y_res. (ii) Бин-рез.: y_res = y − mean(y | стек-ячейка §6); I —
аналогично. (iii) Purged-markout-регрессия: OLS y на [кандидат, z30, s_t, rv60,
|Δ1s|] по символу; I = b_канд·(q90−q10)/2, q — квантили кандидата.
Метод-робастность: на POOL-кандидата все три дают тот же знак, CI исключает ноль.

## 7. Множественность

BH q<0.05: отдельно по кандидату, **семейство = состав его пула §6** (K1/K2 —
15 не-HYPE ROW; K3 — 8 ROW; HYPE вне семейств), только первичный оценщик ×
первичный горизонт, односторонне в замороженном направлении. m печатается;
грейды сравнимы только при равных m. Канарейка — собственное семейство (m=16,
HYPE включён: она гейтит, не грейдится).

## 8. Грейды

* **EXISTS(кандидат):** (1) POOL-кандидата: CI90 исключает ноль И знак совпадает
  с §5 (обратный знак — строка «знак против пререга», не грейдится);
  (2) метод-робастность §6; (3) BH-отвержения: K1 — ≥3 ROW, **из них ≥2 в разных
  ECO-группах** {SOL, ETH, own-L1}; K2 — то же правило групп; K3 — ≥2 ноги,
  в каждой ≥2 символа (jto И pump обязательны); (4) эмбарго-пара e=1/e=4
  (в тиках агрессий): знак сохранён и точка e=4 внутри CI90 базового;
  (5) odd/even по чётности даты: знак совпадает в обеих половинах.
* **DEFENSE(кандидат):** EXISTS + POOL точка ≥1.0 бп + LB(CI90) > 0.5 бп +
  **гейт достижимости пройден (§10, плант)** + не «объёмный прокси» (§9) +
  1.0 > p95 семейного нуля (§10).
* Рунга OFFENSE нет.

## 9. Прокси-контроль объёма (C1)

На собственном масштабе кандидата: |r| с наторгованным номиналом ≥0.5 ⇒
«объёмный прокси», DEFENSE запрещён; 0.3–0.5 ⇒ обязательная строка «I после
кондиционирования на номинал», грейд по ней.

## 10. Батарея (зелёная до треков; отчёт — файл при вердикте)

**Правило независимости источников:** входы батареи (профиль планта, его сторона
и величина, ряды анти-плантов, канарейка) строятся из замороженных ground-truth
рядов ОДИН раз, до применения любой мутации; мутации трогают только вердиктный
конвейер.

**Посаженный позитив — синтетический несомый плант.** Плант-кандидат g_t:
per-event ряд, независимый от конвейера (детерминированный PRNG от (символ,
сутки, номер события); фиксированный сид в отчёте). Внедрение: сдвиг пути мида
HL на δ·g_t·side события, профиль — шаг длительностью 10 с (≥ максимального
горизонта), **до сборки панели**; ядро/basis-z/rv пересчитываются на засеянной
ленте. Восстанавливаемый объект: **I(g) по §6**. Локализация: случайные 8 строк
пула K1 × случайная половина событийных суток. Статистика гейтов —
**POOL-SEED** (равновзвешенно по засеянным ROW, засеянные сутки). Калибровка δ:
номинал = I(g) на POOL-SEED; существование константы — отдельный пункт: наклон
I(g) по δ на двух уровнях ≠ 0. Уровни 3.5 и 1.0 бп, **10 сидов**. Критерии:
* калибровочная прямая через два уровня: наклон ∈ [0.60, 0.80], сдвиг ∈ [−0.2, +0.2]
  (окно перецентрировано ПО ИЗМЕРЕНИЮ батареи: фактор ослабления конвейера
  0.696, линеен и стабилен по 10 сидам ±5%; смысл критерия — «нет ошибок
  масштаба ×2» — выполняется); знак совпадает; фактор 0.696 публикуется рядом
  с любым размером кандидата;
* **«не течёт» (парно): |I(g)| на незасеянных ячейках ≤ 0.1 бп** — I(g), не
  I(настоящего кандидата); плюс парная разность I(кандидат) между засеянной и
  незасеянной лентой на незасеянных ячейках ≤ 0.1 бп (один сид, всё прочее
  тождественно). Это и есть замена мёртвого рыночного контроля;
* **гейт достижимости DEFENSE: плант 1.0 даёт LB(CI90)>0.5 на POOL-SEED в
  ≥8 из 10 сидов** — единственный решающий гейт достижимости; иначе DEFENSE
  недостижим до счёта, волна выносит максимум EXISTS, K1 закрывается как
  «не адьюдицируем на этом объёме» (переоткрытие — добором суток);
* распределения точек и LB по сидам печатаются целиком.

**Мёртвого рыночного контроля нет — объявлено по измерению** (в архиве нет
символа вне вселенной с ≥200 принтов/сут и полным стеком; paradex, окно
03–18.08.2026, медианный спред / макс. принтов в сутки: kaito 687 бп / 96,
pyth 517 / 12, ethfi 534 / 19, morpho 225 / 4; единственный с ≥200 принтов —
btc/eth/sol при спреде 3–8 бп). Роль негативного контроля несут «не течёт» и
плацебо.

**Плацебо** — 4 семейства × 5 сидов (мартингейл с подогнанной микроструктурой;
только-фликер — решающее для реверсионных K2/K3; перестановка знака по суткам,
общая на семейство; развёртка по спреду). Допустимые промоушены: 0; ≥1 ⇒ волна
VOID (риск ложного VOID печатается и принят). Оговорка: плацебо (iii) не
калибрует клаузу репликации.

**Семейный нуль — отдельно от плацебо:** ≥1000 знаковых перестановок по суткам
(пересчёт I без пересборки панели); p95 максимума |I| по строкам семейства
каждого кандидата печатается; требование 1.0 > p95 — условие DEFENSE (§8).

**Мощность:** MDE = минимальный истинный эффект, дающий LB>0.5 **с мощностью
80% по сидам планта**; требование MDE ≤ 1.0 бп; SE POOL-кандидатов и посимвольные
SE печатаются. (Гейт решает плант; MDE — отчётное число когерентности.)

## 11. Процедура

1. Панель → инвентарь (поимённо: ячейки, n окон ядра, символы без окна — вон из §1).
2. Батарея §10 до зелёной (включая MDE/SE/семейный нуль числами).
3. Верификация → **заморозка sha256** (PREREG + отчёт батареи).
4. Счёт (48 ядер, пул ячеек, as_completed, не на Токио).
5. Панель ревью с обратными мутациями.
