# PREREG — Микроструктура, волна 2 (wave-2)

**Статус: ЧЕРНОВИК до адверсариальной панели; заморозка sha256 — после её правок.**
Дата составления: 2026-08-24. Автор дизайна: ассистент, по решениям леджера Бушо
(2026-08-10) и правкам оператора 2026-08-24 (вселенная не «тройка», факторный индекс,
ECO-нога, разложение LM).

## 0. Вопрос и происхождение

Волна 1 (#68, 2026-08-10) оставила один неразрешённый резидуал — LM-1s (локальный
моментум, честный размер +0.8–1.2 бп) — и правило: адьюдицировать его ОДИН раз, внутри
исследования с именованным оценщиком резидуализации (DAR/propagator order-flow
surprise), без отдельных пере-прогонов с новыми часами (запрещено как parameter
shopping). Оператор 2026-08-24 добавил кандидатов якорного класса: бета-остаток к
рыночному индексу и к экосистемной ноге.

**Вопрос волны:** есть ли в {LM-1s, beta-z_MKT, beta-z_ECO} предсказательное
приращение к форвардному ходу мида HL СВЕРХ тройки {basis-z, сюрприз-поток,
реализованная волатильность} — и в каком из двух компонентов (общем/идиосинкратическом)
живёт содержание LM.

**Рамка интерпретации, зафиксированная до счёта:** результат оборонительный.
Наступательная ветка закрыта Stage-0 (UCB95 = −0.869) и переоткрывается только
результатом UCB95>0 по её собственному правилу — не этим исследованием.
Экономическая конвертация приращения: в деньги — только на строке HYPE
(единственная с измеренной планкой 3.154 бп/филл); в «долю снимаемого adverse» —
на клетках с настоящей шириной (выводная полоса ~57% для PUMP-класса, помечена
как деривация).

## 2. Часы и события

* **Часы — событийные, в тиках сделок HL** (решение леджера; календарный вариант
  не гоняется — часовой вопрос решается здесь однократно).
* **События-носители маркаута:** принты HL **at/through тача** (форма at/through

* Сторона агрессора — конвенция `users` (подтверждена 140/140 против биржевой правды).

## 3. Именованный оценщик резидуализации: DAR-сюрприз потока

1. Знаковый ряд ε_t ∈ {−1,+1} по сделкам HL (event-time), объёмное расширение
   w_t = ε_t·log(1+v_t/v̄) (форма A.3 книги; v̄ — медиана объёма сделки за окно оценки).
2. Автокорреляция C(ℓ), ℓ = 1…50 тиков сделок (окно лагов **p = 50** заморожено;
   ориентир плато книги ℓ≈20–50).
3. Ядро K(1…50) из уравнений Юла–Уокера на C(ℓ), решение Левинсоном–Дурбиным.
4. **Walk-forward: ядро для суток d оценивается на сутках d−1** (первые сутки
   оценочного набора не несут событий — только оценку ядра). Внутрисуточного
   пере-фита нет.
5. **Сюрприз s_t = ε_t − Σ K(k)ε_{t−k}**; объёмный вариант s^v_t — из w_t тем же ядром.

## 4. Кондиционирующий стек (вычитается из каждого кандидата)

* **basis-z** — как в волне 1: z отклонения HL-мида от Binance-близнеца, EWMA-окна
  5/30/120 с, все три; вычисление из со-записанных рядов по локальному приёму.
* **Сюрприз-поток** s_t и s^v_t (раздел 3).
* **rv** — реализованная волатильность 1-с приращений HL-мида, трейлинг-окно 60 с.

## 5. Кандидаты (закрытый список; направления заморожены)

* **K1. LM-1s** — локальный моментум 1 с (как в волне 1). Направление: продолжение.
  Адьюдикация: жив ⇔ приращение после ПОЛНОГО стека (§4) по правилу §8.
* **K2. beta-z_MKT** — остаток к рыночному индексу.
  Индекс: **равновзвешенное среднее лог-приращений BTC/ETH/SOL** (Binance-мид).
  β символа: OLS на 60-с барах, трейлинг 3 суток, walk-forward (без текущих суток).
  Состояние: r_t = кумулятивный (лог-альт − β·лог-индекс) за трейлинг 300 с,
  z-скор по σ(r) предыдущих суток. Направление: **реверсия остатка**
  (положительный z ⇒ прогноз вниз для альта).
* **K3. beta-z_ECO** — остаток к экосистемной ноге СВЕРХ рынка.
  Маппинг (извне данных, заморожен): jto→SOL, pump→SOL, ethfi→ETH, pendle→ETH,
  ondo→ETH, crv→ETH, aero→ETH (прокси Base, объявлено), vvv→ETH (прокси Base,
  объявлено). Без ноги (строка отсутствует по правилу): sui, near, dot, inj, hype,
  zro, kaito, gram. Ортогонализация: сначала MKT у обеих ног, затем
  β_e идио-альта на идио-ногу (те же окна, что K2). Направление: реверсия.
* **A1 (анализ, не промоушен). Разложение LM**: ход 1 с = β·индекс + идио;
  LM_common и LM_idio прогоняются тем же конвейером — отчёт, в каком компоненте
  живёт приращение K1.

Других кандидатов нет. Добавление кандидата после заморозки = новая волна.

## 6. Цель и горизонты

* Цель: side-adjusted форвардный ход HL-мида от события (§2), **purged**
  (события с перекрывающимися окнами маркаута прорежены по правилу волны 1).
* **Первичный горизонт: 1 с.** Вторичные: 2/5/10 с — отчётные, непромоутящие.
* Форма распада по горизонту сверяется со степенной ℓ^(1−β−γ) против экспоненты —
  отчётная строка, не критерий.

## 7. Оценщики приращения и метод-робастность

Четыре, как в волне 1: (i) double-sort по кандидату внутри бакетов стека —
**первичный**; (ii) OLS-резидуализация; (iii) бин-резидуализация;
(iv) purged-markout-регрессия.
**Метод-робастность:** знак совпадает и CI исключает ноль у всех четырёх; размер
приращения репортится по первичному.

## 8. Правило вынесения вердикта (грейды)

По каждому кандидату, после полного стека, на оценочном наборе:

* **EXISTS:** CI (кластерный бутстрап по суткам, 90%) исключает ноль; метод-робастно
  (§7); BH q<0.05 по вселенной символов; воспроизведено на ≥3 символах, из них
  ≥1 не-HYPE; переживает эмбарго-пару e=1/e=4 и odd/even сплит.
* **DEFENSE-GRADE:** EXISTS + пулированное филл-взвешенное приращение ≥ 1.0 бп
  (delta_econ, решение оператора 2026-08-10) с LB(CI90) > 0.5 бп.
* **OFFENSE-GRADE:** LB(CI90) ≥ 3.154 бп на строке HYPE. (Ожидаемо недостижимо;
  зафиксировано для полноты. Достижение НЕ открывает наступление само по себе —
  см. рамку §0.)
* Вердикт по A1: «common», «idio» или «не разделимо» — по тому, чей вклад в
  приращение K1 больше при непересекающихся CI; иначе «не разделимо».

## 9. Гейт мощности (outcome-blind)

* Ячейка (символ×сутки) участвует, если: ≥2 000 сделок (tid) И ≥5 000 обновлений bbo.
* Символ входит в вердикт, если ≥15 квалифицированных суток из 21.
* Строка K3 существует только у символов с ногой (§5) — ожидаемо 8.
* Выпавшие ячейки/символы печатаются поимённо в отчёте (никаких молчаливых усечений).

## 10. Батарея честности (прогон обязан быть зелёным ДО треков)

* **Посаженные позитивы, ДВА уровня:** синтетический сигнал, внедрённый в реальную
  ленту, размером **3.5 бп** (сопоставимость с волной 1) и **1.0 бп** (уровень
  решающей планки). Правило: плант 1.0 бп обязан пройти EXISTS в ≥4 из 5 сидов —
  иначе планки ниже фактического уровня сертификации объявляются VOID (механизм
  мезо-пар), и DEFENSE-GRADE не выносится.
* **Плацебо:** (i) мартингейл с подогнанной микроструктурой; (ii) только-фликер;
  (iii) перестановка знака по суткам, общая на семейство (замена дню-шаффлу,
  смещавшему в пользу гипотезы — урок мезо-пар); (iv) развёртка по спреду.
  Ни одно не имеет права промоутнуться.
* **Мёртвый контроль:** символ НЕ-HL площадки, выбранный правилом «максимум принтов
  среди символов paradex с медианным дневным спредом > 100 бп»; требование
  ≥200 принтов/сут — иначе контроль объявляется VOID (вакуумный контроль волны 1
  с 11 принтами не повторять). Ожидание: конвейер не находит сигнала.
* **Контроль на собственном масштабе кандидата** (урок C1: 60-с контроль пропустил
  5-с признак): C1-прокси считается на масштабе каждого кандидата.
* **Frame-rate статистика** — по ячейкам, отчётной строкой.
* **Мутационный контракт** (каждая мутация обязана окрасить именно свой тест):
  * M1 `K:=0` (сюрприз := сырой поток) → тест кондиционирования краснеет
    (детектор OFI-класса утечки);
  * M2 ядро фитится на текущих сутках (снят walk-forward) → self-test заморозки
    краснеет;
  * M3 колонка rv перемешана → строка K1 раздувается ⇒ rv-тест краснеет;
  * M4 ECO-маппинг повёрнут по кругу → строка K3 обязана умереть/самотест краснеет;
  * M5 джойн по venue-времени вместо локального приёма → assert джойна падает;
  * M6 плант не внедрён → тест планта краснеет.
* Отчёт батареи (plants/placebo/мутации) — файл рядом с вердиктом; треки
  отказываются стартовать без зелёного отчёта (паттерн hlalpha).

## 11. Процедура

1. Сборка событийной панели (один раз), инвентарь покрытия с поимённым списком ячеек.
2. Батарея §10 до зелёного. 3. Заморозка PREREG (sha256) — ПОСЛЕ правок
   адверсариальной панели и арифметической проверки когерентности (цель мощности
   против нулевого порога; критерий контроля против размера теста — двойной урок
   мезо-пар). 4. Счёт на оценочном наборе (48 ядер, пул по ячейкам, as_completed;
   НЕ на токийском хосте). 5. Панель ревью с обратными мутациями.
   6. Только после вердикта — вскрытие holdout: подтверждение знака/размера
   EXISTS-кандидатов; расхождение печатается, вердикт не пересматривается задним
   числом.
